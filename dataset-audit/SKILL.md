# Dataset Audit — аудит и подготовка датасета

## Цель

Проверить набор данных до обучения модели, выявить проблемы качества и предложить обоснованную предобработку. Не изменяй исходные данные без необходимости и не скрывай обнаруженные проблемы.

## Порядок работы

1. **Уточни задачу и целевую переменную.** Определи, что требуется предсказывать: класс, числовое значение, последовательность или другой результат. Если целевой столбец не указан и его нельзя надёжно определить, задай один уточняющий вопрос.
2. **Изучи структуру.** Определи размер датасета, названия и типы столбцов, число объектов и признаков, формат целевой переменной. Для изображений проверь размеры, каналы и форматы файлов; для текста — пустые записи и базовые характеристики длины.
3. **Проверь качество.** Найди пропуски, дубликаты, некорректные значения, несоответствие типов, выбросы и подозрительные/постоянные признаки. Для классификации проверь распределение классов.
4. **Проверь риск утечки данных.** Ищи признаки, которые прямо или косвенно раскрывают целевую переменную. Уточни, нет ли повторяющихся объектов или связанных записей, которые могут попасть одновременно в обучающую и тестовую выборки.
5. **Предложи стратегию разделения.** Выбирай обычное случайное разделение только когда оно соответствует природе данных. Используй стратификацию для классификации с дисбалансом классов, групповой split для связанных наблюдений и временное разделение для временных рядов или прогноза будущего.
6. **Составь план предобработки.** Определи обработку пропусков, кодирование категорий, масштабирование числовых признаков, нормализацию изображений и токенизацию текста — только те операции, которые нужны для текущей задачи.
7. **Предотврати утечку при предобработке.** Раздели данные до обучения преобразований. Обучай импутеры, scaler, кодировщики и другие преобразования только на тренировочной выборке, затем применяй их к валидационной и тестовой выборкам. Не используй тестовую выборку для подбора параметров.
8. **Зафиксируй результат.** Представь краткий отчёт, решения по очистке и рекомендуемый следующий шаг. По возможности создай воспроизводимый код, не перезаписывая оригинальный файл.

## Правила

- Не удаляй строки, столбцы или выбросы автоматически без объяснения причины и оценки последствий.
- Не заполняй пропуски произвольными значениями без обоснования.
- Не считай дисбаланс классов ошибкой сам по себе: сначала оцени его масштаб и влияние на метрики.
- Не делай вывод о качестве модели по одному только анализу датасета.
- Если данных недостаточно для уверенного вывода, явно укажи ограничение.
- Сохраняй исходные названия столбцов и единицы измерения, если их изменение не требуется.

## Формат ответа

1. **Краткое описание:** размер и структура датасета, целевая переменная.
2. **Найденные проблемы:** таблица или список с количеством/долей затронутых записей.
3. **Риски:** утечка данных, дисбаланс, нерепрезентативность или другие ограничения.
4. **Рекомендованная подготовка:** конкретные действия и причины.
5. **План разделения:** способ формирования train/validation/test и обоснование.
6. **Следующий шаг:** что можно передать навыку обучения модели.

## Пример активации

Пользователь: «У меня есть CSV с данными о клиентах. Проверь пропуски, дисбаланс целевого столбца и подготовь данные для классификации».

Навык должен провести аудит, предложить корректное разделение и описать предобработку, не обучая модель без отдельной просьбы.
