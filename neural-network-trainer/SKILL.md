# Neural Network Trainer — обучение и оценка модели

## Цель

Организовать корректный и воспроизводимый эксперимент по обучению нейронной сети. Подбирать архитектуру и метрики под задачу, а не использовать одну модель для всех случаев.

## Порядок работы

1. **Определи постановку задачи.** Установи тип задачи (классификация, регрессия, сегментация, генерация, прогноз временного ряда и т. д.), входные данные, целевую переменную и ограничения пользователя.
2. **Проверь готовность данных.** Убедись, что известны способ разделения выборок и шаги предобработки. При отсутствии аудита данных предложи сначала выполнить `dataset-audit`. Не допускай попадания информации из тестовой выборки в обучение.
3. **Выбери метрики.** Для классификации рассмотри accuracy, precision, recall, F1 и ROC-AUC/PR-AUC в зависимости от баланса классов и цены ошибок. Для регрессии — MAE, MSE/RMSE и R². Для других задач подбери профильные метрики. Объясни выбор основной метрики.
4. **Создай базовый вариант.** Начни с простой модели или разумного baseline. Для нейросети определи архитектуру, функцию потерь, оптимизатор, learning rate, размер batch и число эпох. Не усложняй модель без необходимости.
5. **Организуй обучение.** Используй тренировочную выборку для обновления весов, валидационную — для выбора гиперпараметров и контроля обучения, тестовую — для итоговой оценки после выбора модели.
6. **Контролируй переобучение.** Сравнивай кривые обучения и валидации. При необходимости используй early stopping, dropout, weight decay, аугментацию или уменьшение сложности модели. Не применяй все методы одновременно без причины.
7. **Обеспечь воспроизводимость.** Фиксируй seed, конфигурацию эксперимента, версии библиотек, параметры модели и способ разделения данных. Сохраняй лучшую модель по заранее выбранной валидационной метрике.
8. **Оцени итоговую модель.** После выбора конфигурации один раз оцени её на отложенной тестовой выборке. Для классификации покажи confusion matrix и метрики по классам, когда это уместно. Для регрессии проверь распределение ошибок и примеры крупных отклонений.
9. **Сформулируй вывод.** Сравни результат с baseline, укажи ограничения и предложи следующий эксперимент. Не утверждай, что модель хорошая, только на основании высокой accuracy или одной метрики.

## Правила

- Не подбирай гиперпараметры по тестовой выборке.
- Не сообщай вымышленные результаты обучения: отделяй ожидаемый результат от реально полученного.
- Не утверждай, что код запущен, если он не выполнялся в доступной среде.
- Не скрывай ошибки, предупреждения, нестабильность обучения или ограничения вычислительных ресурсов.
- При дисбалансе классов оценивай метрики по классам; при необходимости рассматривай class weights или resampling только внутри обучающей выборки.
- Не используй accuracy как единственную метрику, если классы сильно несбалансированы.
- Если пользователь дал готовую структуру проекта или фиксированные ячейки задания, сохраняй их и изменяй только то, что разрешено.

## Формат результата

1. **Постановка задачи и выбранная метрика.**
2. **Архитектура и обоснование выбора.**
3. **Параметры обучения.**
4. **Код:** зависимости, обучение, валидация и сохранение модели; код должен соответствовать фактической структуре данных.
5. **Результаты:** только фактически измеренные метрики и графики, если обучение было запущено.
6. **Выводы:** сравнение с baseline, признаки переобучения и ограничения.
7. **Следующий эксперимент:** одно-два наиболее обоснованных улучшения.

## Пример активации

Пользователь: «Напиши на PyTorch нейросеть для классификации изображений, обучи её и оцени качество на тестовой выборке».

Навык должен определить формат датасета, предложить архитектуру и метрики, подготовить цикл обучения с валидацией и выдать честный отчёт о фактически полученных результатах.
